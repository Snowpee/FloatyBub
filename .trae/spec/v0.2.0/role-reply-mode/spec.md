# 角色默认回复方式与语音生命周期（v0.2.0）

## 回复展示

角色卡提供文字、语音+文字、纯语音；旧角色默认文字。两种语音模式均默认折叠正文和思考过程，显示灰底语音条，点击播放，紧邻按钮展开/收起文字。仅正文展开时挂载文本操作组，但语音消息不再显示旧朗读按钮；保留复制、编辑等操作。

语音条采用 DaisyUI `btn btn-md` 高度及主题圆角，宽度按音频实际时长映射到 132–280px，并显示秒数。优先将缓存的实际时长与真实波形一起恢复，首次显示语音条时不闪现模拟波形，也不重复读取时长/解码。只有尚未完成分析的音频才先显示模拟细波形，所有可解码音频均在空闲时排队分批计算真实 RMS 波形并平滑替换，不按时长或压缩文件大小跳过。波形分析不阻塞语音就绪和播放。播放进度直接订阅音频 currentTime，已播放部分高亮，停止/结束复位。

新流式回复按角色卡随机延迟范围（默认 1–3 秒，0–60 秒，0/0 关闭）先隐藏整行回复，随后显示至少 700ms 的呼吸占位框与灰色提示。文本完成但没有缓存时显示生成按钮，用户点击后生成；实际语音准备完成后才出现可播放语音条。历史消息不重放模拟延迟。

## 历史语音与显式重生成

- 新回复在本页完成流式生成后自动准备语音；历史消息不自动补生成，缓存缺失时用户点击生成；进入历史会话优先恢复原缓存，缓存完全不存在时显示生成按钮，用户点击后直接排队，不弹窗，也不自动生成。
- 通过消息 ID 和原始正文摘要关联音频版本。参数变化后优先恢复关联的原语音，仍可播放，不因设置变化被替换或打断。
- 缓存 TTL 为 7 天，但过期只代表可更新，不删除已关联消息的原语音。变更参数、过期、手动重生成均先确认。
- 仅当当前有效语音参数与原音频的缓存参数不一致时，在语音后提供重新生成按钮；参数相同（含仅缓存过期）、正常历史恢复、新语音生成成功后均隐藏。最新回复在参数变化后自动弹出「参数变化是否重新生成」，同一目标参数只提示一次；其他历史回复通过自己的按钮弹窗，避免大量历史消息同时打开弹窗。
- 确认只作用于该条消息，不批量刷新整个会话。生成期间旧语音保持可用；只有新音频完整且可读取时长后才替换显示。失败保留原音频并提供错误信息。
- 缓存完全不存在或已被系统/用户清除时，显示生成按钮，用户点击后进入统一队列，不弹确认框；不因页面加载自动生成。失败后可直接重试，正文始终可查看。
- 旧缓存缺少消息关联时，尝试从已知音色和模型版本组合识别本地历史音频并建立关联；无法推断的旧参数不自动生成。

## 统一请求队列与缓存

- 正常聊天朗读、语音回复准备、设置试听共用生成服务，每个页面/APP JS 运行实例最多同时 2 个实际生成任务，其余 FIFO 排队。
- 同内容和有效参数的在途请求合并，不重复请求上游。缓存键包括处理后的文本、音色 ID、朗读模式、模型版本和 API 地址，不包括无关音色备注等字段。
- 普通播放优先读缓存；明确确认重新生成可跳过有效缓存。普通客户端不再先流式请求、失败后并发降级生成；错误只显示并等待用户操作，不自动重试 429 或其他生成错误。
- IndexedDB v2 保留旧 audioCache，并新增 messageAudio 关联。缓存 upsert、容量判断和淘汰在同一事务完成，await transaction.oncomplete 后才释放共享生成任务。
- 磁盘上限 100MB，优先清除未关联消息的最旧音频，不自动淘汰已关联的原语音。写入失败/空间不足时保留最多 20MB 的内存热缓存并提示未持久保存，避免当前会话连续重复请求。
- 缓存仅在当前设备/站点保存，不随账号同步；过期但仍存在的原音频继续保留；缓存完全丢失时等待用户点击生成，不自动补生成。

## 联动取消

- 每个合并请求的使用者拥有独立取消信号；取消一个使用者不会影响其他使用者，最后一个使用者退出才取消共享请求。
- 未开始的排队任务在无人使用后跳过；运行中的任务取消 fetch。切换会话、卸载、参数变更取消不再需要的任务，迟到结果不回写新消息。
- 本地代理和 Vercel TTS 接口监听客户端 aborted/response close，通过 Axios AbortSignal 取消 Fish Audio 请求并销毁上游音频流；正常 response finish 只清理监听器。
- 已被上游接受的任务能否立即终止计算/计费由上游服务决定；不是退款保证。多客户端/多 Vercel 实例的账号级并发限制仍由上游控制，本次队列不是分布式限流器。

## 数据兼容

AIRole.replyMode: text / voice-text / voice，缺省 text。replyDelayMinSeconds/replyDelayMaxSeconds 随角色持久化及云端 settings 同步。

## 波形分析与持久缓存

音频缓存记录包含 analysis（版本、实际时长、96 点真实波形）及独立 revision，无需新增表结构。首次分析后写回同一音频记录；历史恢复将实际时长和波形一起用于首次渲染，不闪现占位波形、不重复解码。

重新生成音频会清除旧分析并建立新 revision。迟到结果只写回匹配的 revision，不能覆盖新音频、复活已清空缓存或擦除已有真实波形；保存分析不刷新音频 TTL。

所有可解码音频都进入串行波形队列，不按时长或文件大小跳过。优先以 8kHz 解码/重采样计算振幅包络，浏览器不支持时回退默认采样率。空闲时间分批计算，完成后平滑替换并缓存；分析不阻塞播放，失败时保留模拟波形。

## 最终交互边界

- 只有在本页面实际观察到流式生成的新回复，在文本完成后自动准备语音；不自动播放。
- 历史消息缓存不存在：显示生成按钮，用户点击后直接生成，不弹确认框，不因页面加载自行请求。
- 有旧音频且有效参数变化：显示重生成按钮并提示确认；生成完成前旧音频仍可播放，参数相同或仅缓存过期不显示重生成按钮。
- 生成任务无论内部等待还是运行，用户界面统一显示「对方语音回复中」，不展示排队等实现状态。

补充回归覆盖：冷启动首次渲染即恢复真实波形、零重复解码和生成请求、分析版本隔离、31 秒及 180 秒/超过 2MB 的音频分析、参数未变时无重生成按钮、生成成功后按钮消失。
